Should you use a pre-release?

  • Beta or RC from an actively maintained project: usually fine. Pin the exact version, read the release notes, test the features you rely on.
  • Alpha: expect changes. Check the issue queue for open critical bugs before you commit.
  • Project seeking co-maintainers or minimally maintained: plan an exit. Look for a replacement or budget for fixing it yourself.

How to install and keep it safe

composer require drupal/entity_clone:2.2.0-beta1
# allow it explicitly if needed
composer config minimum-stability dev
composer config prefer-stable true

Pinning an exact version keeps Composer from drifting to a different pre-release. Re-check the project each month until a stable release appears. Some modules in the table have a different major (for example a 2.x beta) that needs a configuration update, so read the upgrade notes; in the scanner these count as a major-version jump or pre-release line in your quote.
