Composer won't update to Drupal 11: finding and fixing the blocker

The error looks like Your requirements could not be resolved to an installable set of packages, followed by a list of drupal/some_module packages that "require drupal/core ^8 || ^9 || ^10". Each package in that list only allows older Drupal versions. Fix them one at a time.

Step 1: ask Composer exactly what blocks core 11

composer why-not drupal/core 11.4.0

This lists every installed package whose constraint excludes Drupal 11. Those are the only things between you and the upgrade.

Step 2: for each blocker, check for a newer release

composer show drupal/some_module --all | grep versions
composer outdated "drupal/*"

Most active modules already have a release that declares Drupal 11 support. If so, update it while you are still on Drupal 10:

composer require drupal/some_module:^3.0 -W

Look up a module in the atlas to see its minimum Drupal 11 version and the safe step to take now.

Step 3: if there is no release, you have three routes

  1. A community patch. Search the module's issue queue for "Drupal 11 compatibility". If a merge request passes tests, apply it with cweagans/composer-patches.
  2. The lenient plugin, as a stopgap. The mglaman/composer-drupal-lenient plugin lets Composer install a package whose declared constraint excludes Drupal 11. It only changes what Composer allows; it does not make the code work. Test the module before you rely on it, and treat it as temporary.
  3. Replace the module with a maintained alternative, or port it yourself and offer the patch upstream.

Step 4: check custom code too

Composer only knows version constraints. Run Upgrade Status and Rector to find deprecated API calls in your custom modules; the commands are here.

Step 5: then move core

composer require drupal/core-recommended:^11.4 drupal/core-composer-scaffold:^11.4 drupal/core-project-message:^11.4 --update-with-all-dependencies
drush updatedb -y && drush cache:rebuild

Do all of this on a branch or a copy of the site, never production. If the list of blockers is long, paste your composer.lock into the free scanner: it classifies every module and shows what each fix costs.
