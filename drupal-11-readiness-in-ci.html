Check Drupal 11 readiness in CI

You can have your pipeline tell you which Drupal modules block Drupal 11, every time composer.lock changes. The free liftpatch-scan tool reads your lock file, checks each project against drupal.org release data and prints a report. Drupal 10 security support ends December 9, 2026, so a standing check is cheap insurance.

One command

npx github:beingRealFrank/liftpatch-scan composer.lock

Add --json for machine-readable output or --fail-on-blockers to exit with an error when a project has no Drupal 11 release.

As a GitHub Action

name: drupal-11-readiness
on:
  pull_request:
    paths: [composer.lock]
jobs:
  scan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: beingRealFrank/liftpatch-scan@v1
        with:
          file: composer.lock

The report appears in the job summary, listing every project's status, the version to move to and a fixed price for the upgrade.

What the statuses mean

  • Ready: the installed release already supports Drupal 11.
  • Update: a newer release supports Drupal 11; most also still support 10, so you can update now.
  • Major update: Drupal 11 support starts in a new major version; expect configuration changes.
  • Pre-release only: see what to do.
  • Blocker: no release supports Drupal 11. See Composer errors and how to fix them.

Your files stay on your machine. The only network calls go to packages.drupal.org. For custom-code checks and core modules that left core, use the in-browser scan.
