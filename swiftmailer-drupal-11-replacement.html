Swift Mailer and Drupal 11: what to replace it with

The drupal/swiftmailer module has no Drupal 11 release, and its listing shows it as unsupported. If your site sends email through it, you have to move to another mailer before Drupal 11, and test every message type your site sends.

Check if you use it

composer show drupal/swiftmailer
drush pm:list --status=enabled | grep -i swift
drush config:get system.mail interface

If system.mail routes mail through Swift Mailer, it is the active mail system. Also search custom code for swiftmailer references. Paste your composer.lock into the scanner to see it classed as "no Drupal 11 release" with its cost.

The usual replacement

The common choice is the contributed Symfony Mailer module (drupal/symfony_mailer), which is built on the maintained Symfony Mailer library. Plan on these steps, on a copy of the site first:

  1. Install it on Drupal 10 and configure the transport (SMTP host, credentials, or sendmail) to match what Swift Mailer used.
  2. Recreate any per-message settings: from address, reply-to, HTML versus plain text, and any email theme templates.
  3. Send a test of every message your site produces: user registration, password reset, webform notifications, commerce receipts, and so on. Check headers, formatting and delivery.
  4. Switch the mail interface to the new module, uninstall Swift Mailer and remove it with Composer.
  5. Then move core to 11.

Confirm the current recommended replacement and its Drupal 11 release on the module's drupal.org page before you start, because recommendations change. Modules that depended on Swift Mailer, such as some webform and commerce mail handlers, need their own check; the atlas shows each one's status.
